# Audio visualization presets

Audio visualization uses the ordinary **HyperShader Source** and its shared native audio engine.

## Using it (after an intentional installation)

1. In OBS, **Sources → + → HyperShader Source**.
2. Select **Audio Spectrum Orbit** in the shader preset picker, a transparent radial spectrum
   with warm amber / sage colors. Place it over a camera, game, or background.
3. By default it listens to **OBS audio mix 0**. In its properties, enable Sound
   and choose a named **Audio Source** to follow only that OBS source instead.
   Setting the source back to **None** follows the default mix when Input Mode
   is Audio. Normal muted/inactive sources cannot drive a visualizer.
4. Change **Spokes (Interpolated)**, **Inner Radius**, **Spectrum Reach**,
   **Spoke Width**, **Audio Gain**, **Soft Halo**, **Opacity**, and the two colors
   from the ordinary shader parameter UI. The canvas width/height follow the
   existing HyperShader Source controls.

### Available visualizations

**Audio Spectrum Orbit** draws up to 96 radial spokes from
**eight distinct measured FFT bands**. Extra spokes interpolate neighboring
bands; they do not increase measured FFT resolution.

**Phosphor Oscilloscope** is a distinct source shader in the Source category.
Choose **Source / Phosphor Oscilloscope** in the shader preset picker to switch
an existing shader source to it. It draws actual mono PCM samples, not
sinusoids generated by shader time or overall loudness. Its parameters offer
Waveform Gain, Vertical Reach, Horizontal Zoom, Trace Width, Phosphor Glow,
Opacity, Phosphor Color, and optional Scope Graticule. The graticule starts at
zero, preserving clean transparency over a scene.

**Spectral Strata** is a persistent time-frequency record made from real
FFT samples, rather than a geometric oscillator. It maps the existing 512
measured FFT magnitudes across a logarithmic vertical axis and deposits their
amplitudes into new columns on the right edge of a transparent GPU feedback
texture. Older columns shift left on each render and remain visible while
there is room for history; after the history has scrolled out it is gone.
Controls include Spectrum Sensitivity, Contrast Curve, History Pixels Per
Frame, Hold History, Erase History, Opacity, and low/high-frequency colors.
The history progresses per rendered frame, not independently of OBS's render
rate, and the source needs Channel 0 set to **Audio Spectrum**. Each
frequency row is a visualization of the existing 1,024-point FFT, not a claim
of higher time-frequency precision. The effect does not save historical
measurements to disk or infer musical notes.

The audio worker now writes a 512x2 `GS_R8` GPU audio texture. Row 0 contains
FFT magnitudes; row 1 contains 512 downsampled mono PCM values mapped from
[-1,+1] to [0,255] (silence is approximately 128). Channel 0 defaults to
**Audio Spectrum** for Phosphor Oscilloscope and Spectral Strata presets, unless explicitly configured otherwise, and the native renderer binds the channel after texture creation.
The waveform is a short, free-running sample window, **not a trigger-locked
oscilloscope**. If you explicitly override Channel 0, set **Channel 0 → Audio Spectrum** to restore the waveform.

These presets use HyperShader's existing native audio connection, FFT worker,
standard uniforms `audio_band0..7`, shader loader, and OBS GPU renderer.
No Electron, Browser Source, duplicate audio engine, or copied CaYatur code is
included. The artwork and shader were authored for HyperShader; the
source/parameter separation was motivated by
[CaYatur/SoundVisualizer](https://github.com/CaYatur/SoundVisualizer) (MIT).

## Native audio uniform contract (2026-11-22)

HyperShader owns the scalar shader uniforms
`audio_level`, `audio_peak`, `audio_beat`, `audio_envelope`,
`audio_kick`, `audio_snare`, `audio_flux`, `audio_bpm`,
`audio_beat_phase`, `audio_bar_phase`, `audio_beat_confidence`, and
`audio_band0` through `audio_band7` (with `audio_band(index)` convenience
selection in the native stdlib). Each is a separately bound float; other
`audio_*` uniforms are shader-owned controls and are **not** reserved.

The previous `iAudio*` names are **removed**, not maintained as permanent
runtime aliases. Convert custom effect source to these names before loading it;
the Shadertoy import adapter is an external format boundary, not the native
API. Existing user controls such as `audio_gain` are unaffected.
Spectrum Bars retains separate `spectrum_band0..7` shader-owned
`@audio` mappings for its individual gain/smoothing settings.

The OBS plugin binary and bundled shader assets must be upgraded together.
A plugin predating the music-signal binder paired with newer shader assets
produced repeated `Parameter 'iAudioKick' set to invalid size 0, expected 4`
messages. The native audio regression checks real PCM-to-GPU output and
rejects audio parameter-size errors in an isolated OBS render.

Run `bash scripts/verify-native-audio-package.sh` to test **both** Qt-enabled
Linux installation layouts (OBS 32: `bin/64bit`; OBS 33: plugin root)
with their staged shader assets and bundled ONNX Runtime. The root module
uses an install-relative runtime library path, not a developer-machine
path, and the install regression rejects invalid-size audio uniform uploads.

## Verification

In a development build, without installing or touching OBS scene files:

```bash
cmake --build build_x86_64 --target hypershader
scripts/verify-audio-visualizer.sh "$PWD/build_x86_64/hypershader.so" "$PWD/data"
scripts/verify-audio-oscilloscope.sh "$PWD/build_x86_64/hypershader.so" "$PWD/data"
scripts/verify-spectral-strata.sh "$PWD/build_x86_64/hypershader.so" "$PWD/data"
scripts/verify-category-picker.sh "$PWD/build_x86_64/hypershader.so" "$PWD/data"
scripts/verify-source-feedback-cycle.sh "$PWD/build_x86_64/hypershader.so" "$PWD/data"
```

The audio visualizer test runs libobs + OpenGL under isolated Xvfb,
feeds real 440 Hz planar stereo PCM into an OBS audio source, samples the
rendered GPU pixels, checks a visual difference versus silence, changes the
live Gain property to test the GPU response, checks alpha transparency and
that the audio source/Gain properties are actually visible, and exercises
clean source teardown. It must exit 0 and report `PASS=1`.

The oscilloscope test drives 440 and 880 Hz PCM through the same OBS source
and checks frequency-sensitive pixels, live waveform gain, and transparency.
It also disconnects Channel 0 and confirms the frequency response disappears,
then reconnects it and checks the response returns. The optional graticule
must change rendered output while PCM is silent. The spectral-history test
separately verifies genuine 440 Hz and 880 Hz FFT deposition, retained
history after silence, held/erased/restored history, and frequency peaks
occupying different rows of a captured GPU frame. These tests exercise real
libobs/OpenGL pixel rendering rather than just shader compilation.

Linux tests ran on Mesa/OpenGL in an isolated libobs environment. This is
**not** a normal OBS GUI test, NVIDIA performance measurement, or validation
on Windows/macOS. The full MilkDrop runtime, beat-quantized transitions, and
standalone export remain future work. No installed plugin or OBS scene needs
to change while this branch is under development.

## Spectral musical signals (2026-11-18)

The existing native HyperShader audio capture, KissFFT and 512×2 FFT /
waveform texture now produce seven additional scalar uniforms. They are
bound in both normal and BufferA/BufferB/Draw graph rendering without
changing the meaning of existing `audio_beat` or `audio_envelope`:

| Shader uniform | Meaning |
| --- | --- |
| `audio_kick` | 0–1 rising spectral energy in 55–170 Hz |
| `audio_snare` | 0–1 rising spectral energy in 350–4000 Hz |
| `audio_flux` | 0–1 all-band positive spectral change |
| `audio_bpm` | Approximate estimated tempo, 0 until supporting pulses |
| `audio_beat_phase` | Current beat progress [0,1), 0 when tempo unavailable |
| `audio_bar_phase` | Four-beat progress [0,1), 0 when tempo unavailable |
| `audio_beat_confidence` | 0–1 regularity/recency proxy, not certainty |

The new analyzer reuses the existing FFT; it does not start an additional
audio source capture, ML model, or FFT worker. It compares recent magnitude
bins, ignores the DC bin, excludes very-low-energy events and imposes a
0.15-second per-band refractory interval. A run of regular low-frequency
onsets establishes a tempo estimate; after two seconds without low-band
onsets the tempo and phase clear. A source disconnect also clears them.
At the default 1024-point FFT / 48 kHz configuration, the bins are roughly
46.9 Hz apart, limiting the precision of bass-band discrimination.

**Kick and Snare are frequency-region labels, not accurate isolated drum
recognition.** Bass synthesizers and speech may trigger them; tempo may
halve, double, drift or stay unavailable for complex music. There is no
manual tap/lock, tempo grid alignment, dual-resolution FFT or global flash
safety control in this checkpoint. Visual brightness control and
photosensitivity precautions remain the shader author's responsibility.

Verification: pure-C test RED stub → GREEN, checks separate kick/snare,
held tones, inferred 120 BPM at regular 0.5-second pulses, beat/bar phase,
expiry after two seconds, 44.1 kHz reconfiguration, nonfinite input and
reset. Real isolated OBS/OpenGL audio: 440 Hz tone pulses feed
`audio_snare`/`audio_flux` into GPU pixels and 94 Hz pulses feed
`audio_kick`/`audio_flux`; silence restores 0 (two PASS=1 probes).
The preexisting broadband beat/envelope probe also passed unchanged.
Native boundary, Sight interop, audio visualizer and feedback-cycle
probes passed. A first visualizer run reported PASS=1 but its temporary
Mesa cache removal raced; a repeat exited 0 and reported PASS=1.
No normal OBS GUI or real musical performance accuracy test yet.
