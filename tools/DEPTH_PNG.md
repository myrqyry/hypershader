# Depth-bearing PNG interchange (ShaderLab-compatible)

This is a standalone, **standard-library-only Python 3** command-line tool.
It embeds and extracts an existing floating-point depth map in a normal PNG,
using the same private `slDp` ancillary chunk as
[NotRayST/ShaderLab](https://github.com/NotRayST/ShaderLab/blob/main/common/depth_chunk.cpp).
It does **not** estimate depth, capture a game's GPU buffers, or connect to
hypershader/OBS rendering yet. The first purpose is a real, testable,
cross-platform storage boundary for later depth-aware shader effects.

## Usage

Depth input/output is a headerless file of **little-endian IEEE 754 float32**
samples, in row-major order, with one sample per image pixel, normalized to
[0, 1]. No grayscale approximation or computer-vision model is involved.

```sh
python3 tools/depth_png.py embed picture.png depth.f32 picture-with-depth.png --encoding r16
python3 tools/depth_png.py inspect picture-with-depth.png
python3 tools/depth_png.py extract picture-with-depth.png recovered.f32
```

Encoding choices: `r32` (lossless float32), `r16` (65,536 levels),
`r8` (256 levels), `r4` (16 levels). The latter three quantize the data.
For `r16` and `r8`, the stored values use horizontal per-row delta encoding,
as in ShaderLab. Metadata includes a depth-valid flag, virtual far plane,
timestamp, image dimensions, and originating tool identifier.
`--far-plane` changes metadata; it does **not** modify the depth samples.

The tool refuses existing output paths, including broken symlinks, and
publishes completed results without replacing a pre-existing output.
Do not use shared/untrusted output directories without reviewing their
ownership and permission model.

## Verification

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/verify-depth-png-interchange.py -v
```

The test suite covers all four encodings, odd pixel counts, exact preservation
of non-depth PNG chunks, replacement rather than duplication of existing
depth, CRC failures, malformed headers, bounded decompression, malicious
dimensions, the CLI, and overwrite protection.

The four tiny PNGs in `scripts/fixtures/shaderlab-r*.png` were written
with **ShaderLab's original, unmodified C++ `depth_chunk.cpp`** at commit
`00aebdf542627f077c604ded1c1d009ccbe3dcda`. Their decoding is tested on
every run. We also compiled the original C++ encoder/decoder under Linux
(with a compiler-level `-include cmath` for a missing upstream header) and
verified four files generated by each implementation against the other:
**8 cross-implementation operations passed**.

An additional smoke test used an actual 128×96 GPU-rendered shader-gallery
PNG with a *synthetic test gradient* (not true depth). Its original image
pixels were identical after depth embedding, and extraction returned the
expected count of float samples.

## Compatibility / limits

- Mirrors ShaderLab's 108-byte packed little-endian `SLD1` header and
  four compressed encodings. Interoperability is supported by the original
  C++ tests, not merely inferred from matching names.
- Preserves ordinary image chunks and adds the depth chunk before `IEND`.
  A conventional PNG viewer still shows the image and may ignore the
  private depth data.
- Validates PNG framing and CRCs but does **not** decode/fully validate
  the image's `IDAT` payload; an image decoder is needed for that.
- Rejects PNG files exceeding 128 MiB, unsupported depth dimensions,
  more than 16,777,216 depth pixels, invalid compressed sizes, and depth
  data that expands past its declared bounds.
- Requires the depth map to match the PNG dimensions for **embedding**.
  The decoder accepts original ShaderLab depth chunk dimensions.
- The existing `slDp` chunk name is marked safe-to-copy under the PNG
  naming rules. An unrelated image editor could preserve stale depth
  after changing the picture. **Re-embed or regenerate the depth** after
  editing the color image. The tool does not infer that a depth map is
  still geometrically valid.
- No actual depth estimation, OpenGL texture upload, interactive shading,
  or temporal shader settling is implemented here.
